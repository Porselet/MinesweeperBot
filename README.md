**Minesweeper Bot (Сапёр-бот)**

Автоматический бот для игры «Сапёр» (Minesweeper) на C# (.NET). Бот
делает скриншот окна игры, распознаёт состояние поля по шаблонам,
находит ходы с помощью логики и вероятностного анализа, эмулирует клики
мышью.

**Возможности**

-   Компьютерное зрение: распознавание клеток по шаблонам (пиксельное
    сравнение через LockBits, порог 85%).

-   Определение уровня: по ширине клиентской области окна (Новичок /
    Любитель / Профессионал).

-   Детерминированные правила:

    -   «флагов вокруг == число» → открыть остальных соседей;

    -   «закрытых вокруг == недостающих мин» → поставить флаги.

-   Паттерны: 1-2-1 (гориз./верт.), 1-1 (строгий), 1-2-2-1 (строгий,
    мины над двойками).

-   Вероятностный решатель:

    -   строит ограничения из открытых цифр;

    -   разбивает их на связные компоненты (union-find);

    -   для маленьких компонент --- брутфорс с подсчётом решений;

    -   для больших --- эвристика;

    -   выбирает клетку с минимальной вероятностью мины (с учётом
        «фоновых» клеток вне компонент).

-   Безопасные p≈0: клетки с вероятностью 0 открываются как обычный ход,
    а не «вероятностный».

-   Снятие флага при противоречии (флагов вокруг больше, чем число).

-   Эмуляция кликов: левая кнопка --- открыть, правая --- флаг.

-   Автоперезапуск после победы/поражения.

-   Экстренная остановка: F12 работает глобально, в том числе посреди
    серии кликов.

-   Логирование: подробный лог с миллисекундами, матрицей поля и
    действиями бота.

-   Скриншоты: сохраняются при завершении игры (победа/взрыв) с временем
    в имени.

**Требования**

-   ОС: Windows 10/11 (x64).

-   .NET: .NET 10.0 SDK (или новее).

-   Игра: классический «Сапёр» (winmine.exe), окно должно называться
    «Сапер» или «Сапёр».

-   Visual Studio 2022/2026 (или любая IDE с поддержкой C#).

**Сборка**

1.  Клонируй репозиторий:

text

git clone https://github.com/your-username/MinesweeperBot.git

cd MinesweeperBot

2.  Открой решение в Visual Studio.

3.  Убедись, что в свойствах проекта включён «Разрешить небезопасный
    код» (AllowUnsafeBlocks = true) --- TemplateMatcher использует
    LockBits.

4.  Собери проект:

text

dotnet build

**Запуск**

1.  Запусти игру «Сапёр» (окно не должно быть свёрнуто).

2.  Запусти бота:

text

dotnet run

3.  Через 3 секунды бот начнёт играть.

4.  F12 --- экстренная остановка в любой момент.

**Как это работает**

**1. Захват экрана (ScreenCapture.cs)**

Win32 BitBlt копирует содержимое окна игры в Bitmap. Это заметно
быстрее, чем Graphics.CopyFromScreen.

**2. Распознавание клеток (TemplateMatcher.cs)**

Каждая клетка (16×16) сравнивается с эталонами из templates/.
Используется LockBits для прямого доступа к памяти. Порог совпадения ---
85%. Если ни один шаблон не подошёл --- клетка считается закрытой (-1).

**3. Логика (Solver.cs + Rules/ + Probability/)**

DeterministicRules:

-   «флагов вокруг == число» → открыть остальных;

-   «закрытых вокруг == недостающих мин» → поставить флаги.

PatternRules:

-   1-2-1: 1-2-1 в строке/столбце, мины сверху/снизу;

-   1-1 (строгий): у каждой 1 ровно один закрытый сосед, и это одна и та
    же клетка → мина там;

-   1-2-2-1 (строгий): у крайних 1 ровно один закрытый сосед --- клетка
    над соответствующей 2 → мины над двойками (пример: 0 F F 0 / 1 2 2
    1).

ProbabilitySolver (когда детерминированных ходов нет):

-   собирает ограничения из всех открытых цифр;

-   разбивает на связные компоненты;

-   для компонент ≤ 18 клеток --- брутфорс с подсчётом решений по каждой
    клетке;

-   для больших --- эвристика;

-   учитывает «фоновые» клетки вне компонент (minesLeft /
    backgroundCount);

-   выбирает клетку с минимальной вероятностью мины;

-   клетки с p≈0 открываются как обычный ход (не «вероятностный»);

-   при противоречии (minesNeeded \< 0) снимает флаг.

**4. Клики (InputSimulator.cs)**

Win32 SetCursorPos + mouse_event. Левая кнопка --- открыть, правая ---
флаг.

**5. Экстренная остановка**

Win32 GetAsyncKeyState(VK_F12) проверяется перед каждым ходом и внутри
серии кликов.

**Производительность**

Замеры на «Профессионале» (30×16, 480 клеток), по логам:

  -----------------------------------------------------------------------
  Этап                                               Время
  -------------------------------------------------- --------------------
  Скриншот                                           \~55--75 мс

  Распознавание (480 клеток)                         \~10--14 мс

  Поиск ходов (детерминированные)                    \~0--5 мс

  Вероятностный поиск (тупик)                        \~1--10 мс

  Один клик                                          \~80--130 мс

  Один ход (1--2 клика)                              \~100--300 мс
  -----------------------------------------------------------------------

Победа на «Профессионале» --- 78 ходов, \~1 мин 40 сек (по логам).

**Настройка**

Параметры в Program.cs:

csharp

const int DelayAfterClick = 20; *// Пауза после клика (мс)*

const int DelayBetweenTurns = 50; *// Пауза между ходами (мс)*

const int DelayBeforeStart = 3000; *// Задержка перед стартом (мс)*

Координаты сетки (StartX, StartY, CellSize) заданы в GameLevel.cs для
каждого уровня. Сейчас для всех трёх уровней используются одни и те же
значения (StartX=15, StartY=101, CellSize=16), потому что окно Сапёра
использует общую сетку. Если после калибровки окажется иначе --- их
можно задать per-level.

**Калибровка**

1.  Запусти бота с параметрами по умолчанию.

2.  Если поле распознаётся неверно (видны M там, где их нет, или F на
    открытых клетках) --- откалибруй StartX, StartY, CellSize в
    GameLevel.cs.

3.  Для отладки можно сохранить скриншот поля с наложенной сеткой (см.
    ScreenCapture.cs).

**Известные ограничения**

-   Только Windows (Win32 API).

-   Классический «Сапёр» (winmine.exe). Для других версий нужна
    калибровка координат.

-   Паттерн 1-2-1 проверяет только горизонтальные и вертикальные
    последовательности (диагонали не проверяются).

-   Паттерны 1-1 и 1-2-2-1 --- строгие версии, срабатывают реже
    классических «широких» паттернов, но не врут.

-   Subset rule (сокращение ограничений) не реализован --- это следующий
    шаг для повышения winrate.

-   Вероятностный решатель не учитывает «свои» флаги отдельно от
    распознанных --- при рассинхроне может быть небольшой шум.
